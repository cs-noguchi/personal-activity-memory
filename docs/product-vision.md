# Product Vision

## 1. プロダクト概要

### コンセプト

「自分の過去を検索できる。」

PC、スマートフォン、位置情報、GitHub、カレンダーなどに分散している個人の行動履歴を自動的に収集・統合し、AIによって「いつ・どこで・何をしていたか」を検索・振り返りできるPersonal Memoryサービスを提供する。

一般的なタイムトラッキングサービスが「何分作業したか」を記録するのに対して、本サービスでは、

**Activity Tracking → Activity Understanding → Personal Memory**

までを目指す。

## 2. 解決したい課題

日々の行動や作業は複数のサービス・デバイスに分散している。

例えば、

- PCでどのアプリを使用していたか
- どのWebページを閲覧していたか
- GitHubで何を変更したか
- どこへ移動したか
- どの予定に参加したか
- 何を調べたか
- いつ設定変更を行ったか
- 何を学習したか

といった情報は個別には残っているものの、後から横断的に確認することが難しい。

結果として、

- 「昨日の15時ごろ何をしていた？」
- 「AWSの設定を変更したのはいつ？」
- 「先週Spring Bootについて何を学習した？」
- 「あの問題を解決したとき何をした？」

といった、自分自身の過去に関する情報を簡単に思い出すことができない。

## 3. 提供価値

複数の行動データを時系列で統合し、AIによって意味のある「記憶」に変換する。

例えば、

**質問**

「先週、認証機能について何をやった？」

**回答イメージ**

月曜日にSpring Securityについて約45分調査。
水曜日にGitHub Issue #31の対応として認証処理を修正し、3件のテストを追加。
木曜日に関連するPull Requestを作成し、同日17:32にマージ。

このように単純なアプリ利用履歴ではなく、

「何を目的として、何を行い、その結果何が起きたか」

まで復元できる状態を目指す。

## 4. 想定ユーザー

初期ターゲットは以下とする。

### メインターゲット

- ソフトウェアエンジニア
- フリーランス
- 個人開発者
- 複数プロジェクトを並行する知的労働者

特に、

- 「以前やった作業内容を忘れる」
- 「設定変更した時期を思い出せない」
- 「何に時間を使ったか振り返りたい」

という課題を持つユーザーを対象とする。

将来的には、仕事だけではなく日常生活を含めたPersonal Memoryへ拡張する。

## 5. 既存サービスとの差別化

### Google Maps Timeline

- 主な価値：「どこにいたか」
- 本サービス：「そこで何をしていたか」

### ActivityWatch

- 主な価値：「どのアプリ・Webサイトを何時間使用したか」
- 本サービス：複数の行動履歴を関連付け、AIが作業内容を理解する。

### RescueTime / Rize / Timely

- 主な価値：生産性・勤務時間・タイムトラッキング
- 本サービス：時間管理ではなく「記憶の検索」を目的とする。

### 本サービスの立ち位置

Time TrackerではなくPersonal Memory。

「何時間使ったか」ではなく、「自分は何をしていたのか？」に答える。

## 6. KPI

初期段階では売上を最重要KPIにはしない。

### Phase 1

- 自分自身が毎日利用できる
- 1か月以上安定稼働
- AI検索が実用になる

### Phase 2

- 外部ユーザー10人
- 継続利用ユーザー5人以上

### Phase 3

- 登録ユーザー100人
- MAU 30人以上

重要なのは、第三者が継続して利用するプロダクトになること。

## 7. 収益化

初期版は無料提供を想定する。

ユーザー需要が確認できた場合のみ、有料機能を検討する。

例：

- 長期履歴保存
- 高度なAI検索
- 複数デバイス同期
- 外部サービス連携
- 高度な分析
- Personal AI Memory

収益化自体を初期目標とはしない。

## 8. 本プロジェクトで習得する技術

本プロジェクトでは実際のサービス運営を通じ、

- TypeScript
- React
- Next.js
- NestJS
- PostgreSQL
- REST API
- OAuth
- Docker
- AWS
- IaC
- CI/CD
- Monitoring
- Security
- Event Driven Architecture
- AI / LLM
- RAG / Search
- GitHub
- Agentic Development

を実践的に習得する。

技術を習得するためにプロダクトを作るのではなく、プロダクト上の課題を解決するために必要な技術を習得する。

## 9. エンジニアとしてのキャリア上の目的

本プロジェクトは単なる学習用ポートフォリオではない。

実際に公開し、ユーザーに利用してもらい、継続的に運用・改善する。

1年後には、

「TypeScriptを勉強しました」ではなく、

「TypeScript / Next.js / NestJS / AWS等を使用したWebサービスを企画・設計・開発し、実ユーザー向けに継続運用している」

状態を目指す。

GitHubでは、

- Source Code
- Architecture
- CI/CD
- Infrastructure
- ADR
- Issues
- Pull Requests
- Test
- Release History

などを公開し、技術力を確認可能にする。

## 10. 1年後の目標状態

- **商用・公開プロダクト**：実際にアクセスできるサービスが存在する。
- **GitHub**：第三者がコード・設計・開発履歴を確認できる。
- **実ユーザー**：少人数でも継続利用ユーザーが存在する。
- **開発経験**：企画から本番運用まで一貫して経験している。
- **AI Development**：AI Agentを利用した実践的な開発プロセスを構築している。

## 11. プロダクトの最終ビジョン

単なるActivity Trackerではなく、「自分自身の外部記憶装置」を目指す。

人間が、

- 「いつやった？」
- 「何をした？」
- 「何を学んだ？」
- 「どうやって解決した？」

を思い出す必要そのものを減らす。

最終的には、

**Your life, searchable.**

自分の過去を検索できるPersonal Memory Platformへ発展させる。
